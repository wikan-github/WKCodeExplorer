WK Code Explorer: Feature Report

Implemented features with their behaviour, followed by the features still to do.

1. Copy

FeatureBehaviourStatus
Copy a class (single) Builds //MMWIN:CLASSCOPY text: a //UNIT: header with the source unit, a unit wrapper, the type block with the { Name } comment, and all method bodies including class procedure, class function, destructor. Verified in IDE
Copy a member (method or property) Builds //MMWIN:MEMBERSCOPY text. Works from the Interface node and the Implementation node, with the same output. Verified in IDE
Copy a standalone routine (single) Builds //MMWIN:MODULECOPY: public routines carry their declaration and body, private routines carry the body only. Overloads each keep their own declaration. Nested routines are copied with their parent. Verified in IDE
Copy a nested routine on its own Copies only that routine (PROCEDURECOPY). Verified in IDE
Multi-select copy (Ctrl-click, Shift-click) One //MMWIN:MODULECOPY block with //UNIT:, classes and standalone routines in source order. Class bodies are matched by qualified header. Block ends with a blank line and end.. Verified in IDE

2. Paste

FeatureBehaviourStatus
Paste a single class into a unit Class goes inside the existing interface type block (type line added only when the unit has none). {$M+} added when the class has a published section. Existing name is renamed (THuman_1, THuman_2). Bodies go to implementation. Verified in IDE
Paste a single class into a selected class Same as the unit paste: the class is a new declaration in the existing type block. The source unit is added once to uses; no change if the clip has no //UNIT: line. Class-qualified bodies are pasted. Verified in IDE
Paste a single member into a class Member goes under its original visibility. A nested routine becomes a private method. Repeated paste shows "Routine already exists". Verified in IDE
Paste a member with no class selected (Module) Becomes a private standalone routine in implementation, with the TOld. prefix removed from the header. Verified in IDE
Paste a standalone routine (single) into the Module Public routine: declaration in interface, body in implementation. Private routine: body only. Verified in IDE
Paste a standalone routine into a class Becomes a method of the class. Visibility follows the copied item. Verified in IDE
Overloaded routine paste Each overload keeps its own declaration and overload; directive. Verified in IDE
Multi-select paste into the Module Classes go into a new type block in interface (type line added). Source unit added once to uses. Declarations go to interface, bodies to implementation. Duplicates are skipped with a message naming them. Single Ctrl+Z undoes the whole paste. Verified in IDE
Multi-select paste into a class: block with classes Refused with the message "no procedures found to convert the method"; nothing changes. Verified in IDE
Multi-select paste into a class: routines only Each routine becomes a method, in clip order (no sorting). Overloads kept. Appended after the existing methods in the matching section. Duplicates are skipped with a message. Checks (a) to (d) verified; Ctrl+Z check not yet verified

3. Delete

FeatureBehaviourStatus
Delete a class (interface or implementation section) Removes the declaration and its method bodies. The { Name } comment and empty visibility labels are kept. One Ctrl+Z restores it. Verified in IDE
Delete a method from the Interface or Implementation node Interface node: removes the declaration and body. Implementation node: removes the body and its declaration. Overloads: only the selected one. Verified in IDE
Delete a standalone routine Public routine: declaration and body. Private routine: body only. Verified in IDE
Delete a module variable or constant Removes only that line. Verified in IDE
Delete disabled cases Non-class types, nested routines and local variables are not offered. Verified in IDE
Confirmation and cancel One generic Yes/No dialog before any change. Cancel leaves the source unchanged. Verified in IDE

4. Ctrl+L: Add local variable

FeatureBehaviourStatus
Trigger and dialog Ctrl+L on an identifier in a routine body opens the Add local variable dialog. Name is prefilled. Type name defaults to Integer. Requires removing the Lazarus Find Next Ctrl+L alternate (user setting). Verified in IDE
Insertion Routine with a var section: new declaration is the first line under var, indented two spaces. Routine without one: var is created above begin. A name typed in a nested routine's own var section (Fill, yy) creates var yy: Integer; inside Fill. Outer body below nested routines works. Verified in IDE
Duplicate and invalid names Duplicate name: "Variable already exists" confirmation (OK inserts the redeclaration). Invalid name (e.g. 123myVar): confirmation before inserting. Verified in IDE
Type name list Primitive types, unit-level types, current-routine local types and stored History entries (in the separate History combo). Filters as you type (case-insensitive). Inline type T = ... suggests T. Class members do not appear. Verified in IDE
History list and Edit... Separate History combo, up to 30 entries, most recent first. Selecting an entry fills Type name. OK saves the chosen type. Cancel does not. Edit... opens the history file in the Lazarus editor. Verified in IDE

5. Tree and view

FeatureBehaviourStatus
Default view Source order opens by default. The category toggle is still available. Verified in IDE
Refresh after Delete and Paste The tree refreshes automatically after Delete and Paste, even when the tree has focus. Verified in IDE
Class in the Implementation section Delete works for classes declared after implementation. Verified in IDE

6. Toolbar

FeatureBehaviourStatus
Icon-only toolbar on the right side of the tree A vertical frame with five TBitBtn buttons: Copy, Paste, Delete, Rename and Jump to. Icons come from the IDE image list (laz_copy, laz_paste, laz_delete, item_rename, menu_jumpto_section); no image files were added. Implemented
Button behaviour and enable state Each button forwards to the same handler as its popup item. A 100 ms TTimer calls the existing TreePopupmenuPopup state computation, so buttons are enabled/disabled on selection without right-click. Popup logic and enable rules are unchanged. Implemented
